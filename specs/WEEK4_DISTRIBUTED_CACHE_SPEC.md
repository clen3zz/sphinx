# 第 4 周规格：静态客户端分片

- 状态：Completed（2026-08-24）
- 依赖：第 2、3 周规格全部验收通过
- 目标：在不改造 `sphinxd` 为集群节点的前提下，通过一致性哈希和同步客户端完成最小跨节点分片

## 1. 项目对“分布式缓存”的限定

本周实现的是**客户端侧静态分片**：多个独立 `sphinxd` 进程各自保存一部分键，客户端根据相同的一致性哈希规则选择唯一节点。

```text
                    ClusterClient
                          │
                  ConsistentHashRing
                    ┌─────┼─────┐
                    │     │     │
                 Node A Node B Node C
                 sphinxd sphinxd sphinxd
```

节点之间不通信，也没有副本和自动故障转移。这一边界必须在 README、演示和简历表述中保持一致。

## 2. 模块 A：静态节点配置

### 2.1 输入形式

集群客户端和命令行工具接受：

```text
--nodes host1:port1,host2:port2,host3:port3
```

本周期只要求 IPv4 地址或不含冒号的主机名，不解析 IPv6 字面量。

### 2.2 功能需求

- **W4-CONFIG-01**：配置必须至少包含一个节点。
- **W4-CONFIG-02**：每个节点必须包含非空主机名和 1～65535 的十进制端口。
- **W4-CONFIG-03**：重复端点必须被拒绝，不能在哈希环中获得双倍权重。
- **W4-CONFIG-04**：配置中不得包含空白字符；节点 ID 固定为 `<原始 host>:<十进制 port>`，其中端口去掉前导零，主机名保持输入形式，不做 DNS 或大小写归一化。
- **W4-CONFIG-05**：节点在输入中的先后顺序不得影响最终键映射。
- **W4-CONFIG-06**：配置在客户端构造后保持不变；运行中不支持增删节点。

### 2.3 直接测试

节点配置单元测试至少覆盖：单节点、多节点、空配置、缺失端口、非法端口、重复节点、输入顺序变化。

## 3. 模块 B：一致性哈希环

### 3.1 功能需求

- **W4-RING-01**：每个真实节点固定建立 64 个虚拟节点，虚拟节点标识为 `<node_id>#<index>`。
- **W4-RING-02**：键和虚拟节点必须复用项目现有的 MurmurHash3 32 位算法与固定 seed `1`，不得引入新的哈希依赖。
- **W4-RING-03**：环上条目按 `(hash, node_id, virtual_index)` 排序；即使发生哈希碰撞，结果也必须确定。
- **W4-RING-04**：路由时选择第一个哈希值大于等于键哈希的条目；超过环尾时回绕到第一个条目。
- **W4-RING-05**：相同节点集合和相同键必须始终选择相同节点，且不受节点输入顺序影响。
- **W4-RING-06**：向环中加入一个节点后，原来发生迁移的键只能迁移到新节点；删除一个节点后，原来不属于被删除节点的键不得改变归属。
- **W4-RING-07**：空环调用路由必须显式报错，不得返回无效引用或默认节点。

### 3.2 最小设计约束

- 哈希环只负责纯计算，不建立网络连接，也不感知节点健康状态。
- 虚拟节点数固定为 64，不增加权重、分区副本或运行时调参。
- 可以把现有键哈希提取为共享的小函数，但不得建立通用哈希框架。

### 3.3 直接测试

一致性哈希单元测试必须固定输入并覆盖：

1. 单节点所有键都映射到该节点；
2. 三节点分布中每个节点至少获得一个键；
3. 相同配置重复构造结果一致；
4. 打乱节点顺序后结果一致；
5. 环尾回绕；
6. 哈希碰撞时结果确定；
7. 对至少 10,000 个固定键检查 W4-RING-06 的精确迁移性质。

分布是否“足够均匀”只作为观察数据，不设置比例断言，避免把统计波动当成功能错误。

## 4. 模块 C：同步集群客户端

### 4.1 支持操作

客户端只提供：

- `set(key, value)`，固定使用 `flags=0`、`exptime=0`；
- `get(key)`；
- `delete(key)`；
- `route(key)`，返回负责该键的节点，便于测试和演示。

### 4.2 功能需求

- **W4-CLIENT-01**：每次操作必须先通过哈希环选择唯一节点，然后只向该节点发送请求。
- **W4-CLIENT-02**：客户端必须使用 Memcached ASCII 帧并完整处理部分读写，不得假设一次 `send` 或 `recv` 完成整个消息。
- **W4-CLIENT-03**：客户端为每个节点惰性建立一个 TCP 连接，并可以在后续请求中复用。
- **W4-CLIENT-04**：连接断开、超时、协议响应非法时必须返回包含目标节点的明确错误；不得把网络错误伪装成 cache miss。
- **W4-CLIENT-05**：一次操作失败后关闭对应连接；下一次操作可以重新建立连接，但不得在同一次操作中自动重试。
- **W4-CLIENT-06**：客户端默认连接和 I/O 超时均为 2 秒，避免测试永久挂起。
- **W4-CLIENT-07**：客户端实例不承诺线程安全；需要并发时，每个线程使用独立实例。
- **W4-CLIENT-08**：`get` 必须区分命中、未命中和网络/协议错误，并返回值的完整字节序列。

### 4.3 最小设计约束

- 使用同步 socket 即可，不复用服务端 Reactor，也不引入异步运行时、连接池或 RPC 框架。
- 不支持客户端多键 `get`；调用方逐键请求。
- 不支持 `add`、`replace`、`incr/decr`、TTL 和 `flags` 的集群客户端封装；服务端已有能力不受影响。

### 4.4 直接测试

- 使用本地伪服务端或 `socketpair` 测试部分响应、提前断开、超时和非法协议响应。
- 启动真实单节点验证 `set/get/delete` 和连接复用。
- 停止目标节点后验证操作在超时时间内返回错误而不是 miss；重启节点后下一次操作能够重新连接。

## 5. 模块 D：最小命令行工具

新增 `sphinx-cluster` 可执行文件，只提供便于演示的四个子命令：

```text
sphinx-cluster --nodes <list> route <key>
sphinx-cluster --nodes <list> set <key> <value>
sphinx-cluster --nodes <list> get <key>
sphinx-cluster --nodes <list> delete <key>
```

### 5.1 功能需求

- **W4-CLI-01**：参数错误和客户端错误必须写入标准错误并返回非零退出码。
- **W4-CLI-02**：`route` 输出唯一的 `host:port`。
- **W4-CLI-03**：`set` 成功输出 `STORED`；`get` 命中输出原始值，未命中输出 `NOT_FOUND`；`delete` 透传 `DELETED` 或 `NOT_FOUND`。
- **W4-CLI-04**：命令行工具只调用集群客户端公开接口，不重复实现路由和协议解析。

### 5.2 直接测试

CLI 测试至少覆盖帮助信息、非法配置、未知子命令、四个合法子命令的输出和退出码。

## 6. 模块 E：三节点集成测试

新增默认接入 CTest 的多节点测试，启动三个配置不同端口的 `sphinxd` 进程，每个节点使用 1 个线程、8 MiB 内存和 1 MiB Segment。

### 6.1 功能需求

- **W4-IT-01**：测试必须为三个节点分别找到至少一个归属键，并通过集群客户端写入和读取。
- **W4-IT-02**：写入后直接连接负责节点必须命中，直接连接另外两个节点必须未命中，证明数据确实按节点隔离。
- **W4-IT-03**：删除后通过集群客户端和负责节点直接读取都必须未命中。
- **W4-IT-04**：相同节点列表使用不同输入顺序时，`route` 结果必须相同。
- **W4-IT-05**：目标节点停止后，客户端必须返回节点错误；测试不得期待自动切换到其他节点。
- **W4-IT-06**：测试结束时必须只清理自己启动的三个进程和临时文件。

### 6.2 直接测试

三节点场景必须作为独立 CTest 用例完整运行，任何节点启动失败、断言失败、超时或子进程异常退出都必须使测试返回非零状态。

## 8. 实现顺序

1. 节点配置解析及单元测试；
2. 一致性哈希环及单元测试；
3. 同步单节点协议客户端及错误测试；
4. 将路由与客户端组合为集群客户端；
5. 增加最小 CLI；
6. 完成三节点集成测试；
7. 完整执行第 1～3 周回归和通用验收门槛。

## 9. 完成定义

- 每个模块的直接测试全部通过；
- 三个真实服务进程间的数据分片能够被自动化测试证明；
- 节点顺序不影响路由，成员变化满足一致性哈希性质；
- 节点故障被明确返回且不会被伪装为未命中；
- README 明确写成“静态客户端分片”，不声称已实现副本、高可用或动态集群。

## 10. 本周非目标

- 服务端代理或透明转发；
- 服务发现、健康检查、心跳和动态成员变更；
- 副本、读写 quorum、一致性协议和自动故障转移；
- 请求重试、熔断、限流和连接池；
- 节点扩缩容时的数据迁移或再平衡；
- 跨节点多键查询和全局 `stats`；
- 持久化、鉴权、TLS 和 LLM KV Cache。
