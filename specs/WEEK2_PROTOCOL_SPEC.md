# 第 2 周规格：最小缓存协议补全

- 状态：Completed（2026-08-24）
- 依赖：第 1 周单机正确性基线 `11a75a5`
- 目标：补齐多键读取、删除和原子计数，使缓存具备最小但完整的常用操作闭环

## 1. 范围

本周只增加以下命令：

```text
get <key> [<key> ...]\r\n
delete <key>\r\n
incr <key> <delta>\r\n
decr <key> <delta>\r\n
```

单键 `get` 必须继续兼容。`set`、`add`、`replace`、TTL、`flags` 和 `version` 的现有语义不得改变。

## 2. 模块 A：协议解析

### 2.1 功能需求

- **W2-PROTO-01**：解析器必须识别一到多个由空格分隔的 `get` 键，并保持输入顺序。
- **W2-PROTO-02**：解析器必须识别 `delete` 的单个键。
- **W2-PROTO-03**：解析器必须识别 `incr`、`decr` 的单个键和一个无符号 64 位十进制增量。
- **W2-PROTO-04**：命令头未收到完整 `\r\n` 时必须返回“需要更多数据”，不得提前执行或返回错误。
- **W2-PROTO-05**：解析一条命令时不得消费后续流水线命令的任何字节。
- **W2-PROTO-06**：完整但不符合本周语法的命令行必须沿用现有 `ERROR\r\n` 行为；`delta` 超出无符号 64 位范围时必须返回 `CLIENT_ERROR invalid numeric argument\r\n`，服务不得崩溃。
- **W2-PROTO-07**：解析结果中的键在请求缓冲区被移动或释放后不得继续以悬空 `string_view` 使用；跨线程消息和聚合状态必须拥有所需数据。

### 2.2 最小设计约束

- 可以扩展当前 Ragel 语法和 `Parser` 的解析结果。
- 不得为了新增三个命令引入通用 AST、命令注册框架、反射或插件系统。
- 不实现 `noreply`、CAS、Binary Protocol 或 Meta Protocol。

### 2.3 直接测试

在 `sphinxd/test/protocol_test.cpp` 中至少覆盖：

1. 单键和多键 `get`；
2. `delete`；
3. `incr`、`decr` 的 `0`、`UINT64_MAX` 和溢出输入；
4. 分片命令头；
5. 新命令与旧命令混合流水线；
6. 完整非法命令不影响下一条合法命令。

## 3. 模块 B：删除

### 3.1 功能需求

- **W2-DEL-01**：删除存在且未过期的键必须返回 `DELETED\r\n`。
- **W2-DEL-02**：删除不存在或已经过期的键必须返回 `NOT_FOUND\r\n`。
- **W2-DEL-03**：删除成功后，后续 `get` 必须 miss，后续 `add` 必须能够重新写入同名键。
- **W2-DEL-04**：命令必须按键哈希路由到唯一存储线程，不得在连接线程直接修改其他分片。
- **W2-DEL-05**：删除只使当前索引对象失效，不得破坏日志内存中其他键或错误删除覆盖后的新版本。

### 3.2 最小设计约束

- 必须复用现有 `Log::remove()` 和跨线程命令通道。
- 不实现延迟删除、删除锁、墓碑同步或持久化删除记录。

### 3.3 直接测试

- `logmem_test.cpp`：存在键、缺失键、覆盖后删除、过期键删除、删除后重新写入。
- `network_test.py`：在 1/4/8 线程下验证 `set -> delete -> get -> add -> get` 完整链路。

## 4. 模块 C：原子计数

### 4.1 功能需求

- **W2-ARITH-01**：`incr` 将现有值视为无符号 64 位十进制整数并加上 `delta`，返回新的十进制值和 `\r\n`。
- **W2-ARITH-02**：`decr` 做减法；结果小于 0 时固定为 0，不发生下溢回绕。
- **W2-ARITH-03**：`incr` 使用无符号 64 位模运算，超过 `UINT64_MAX` 时回绕。
- **W2-ARITH-04**：键不存在或已经过期时返回 `NOT_FOUND\r\n`，不得自动创建键。
- **W2-ARITH-05**：现有值不是完整的无符号十进制整数时返回 `CLIENT_ERROR cannot increment or decrement non-numeric value\r\n`，原值不得改变。
- **W2-ARITH-06**：成功更新后必须保留原对象的 `flags` 和绝对过期时间。
- **W2-ARITH-07**：同一键的计数操作必须在其所属存储线程中串行执行；多个客户端并发增加同一键时不得丢失更新。
- **W2-ARITH-08**：更新仍通过日志追加和旧对象失效完成，不得为计数器增加第二套存储结构。

### 4.2 数字判定

有效值只能包含一个或多个 ASCII 数字 `0`～`9`。以下内容均视为非数字：

- 空值；
- 正负号；
- 前后空格；
- 小数；
- 超过无符号 64 位范围的十进制文本。

前导零允许存在，但成功运算后的响应和值使用不带多余前导零的标准十进制形式。

### 4.3 直接测试

- `logmem_test.cpp` 或独立算术单元测试：正常加减、减到 0、回绕、非数字、缺失、过期、`flags`/TTL 保留。
- `network_test.py`：1/4/8 线程下的命令响应；多个连接并发对同一键执行固定次数 `incr`，最终值必须等于成功操作总数。

## 5. 模块 D：多键读取

### 5.1 功能需求

- **W2-MGET-01**：一个 `get` 命令可以包含一个或多个键。
- **W2-MGET-02**：每个键都必须按自己的哈希值路由，单个请求可以同时访问多个存储线程。
- **W2-MGET-03**：命中的键按请求中的出现顺序返回；未命中和已过期的键不产生 `VALUE` 块。
- **W2-MGET-04**：重复键按出现次数分别返回，行为必须确定。
- **W2-MGET-05**：整个命令只返回一个结尾 `END\r\n`，并且只占用连接上的一个请求序号。
- **W2-MGET-06**：所有子结果到齐前不得发送部分响应，以免后返回的键出现在 `END\r\n` 之后。
- **W2-MGET-07**：某个子请求因跨线程请求队列已满而无法提交时，整个命令最终只返回 `SERVER_ERROR request queue is full\r\n`，不得混合部分 `VALUE` 响应。
- **W2-MGET-08**：客户端提前关闭时，未完成的聚合结果必须安全丢弃，不得访问已经销毁的连接或泄漏聚合状态。

### 5.2 一致性边界

多键 `get` 不提供跨键快照。每个键只保证读取其所属线程执行该子请求时可见的值。该限制必须写入代码注释或开发文档，不得为了快照语义引入锁、事务或全局屏障。

### 5.3 最小设计约束

- 一个键一个子请求即可，不要求按目标线程批量合并消息。
- 聚合状态只需要记录原始位置、未完成数量、命中结果和是否发生错误。
- 不建立通用 Future/Promise、任务图或 RPC 框架。

### 5.4 直接测试

在 `network_test.py` 中至少覆盖：

1. 全部命中、全部未命中和命中/未命中混合；
2. 已过期键；
3. 重复键；
4. 能够落到不同工作线程的键集合；
5. 大值导致部分写；
6. 多键 `get` 与 `set/delete/incr` 混合流水线；
7. 请求发出后客户端立即关闭；
8. 多连接并发多键读取。

## 9. 本周非目标

- `gets`、CAS、`touch`、`append`、`prepend`；
- `noreply`、`stats`、`flush_all`；
- UDP、Binary Protocol、Meta Protocol；
- 全局多键快照、事务或跨分片锁；
- 针对极端内存耗尽的工业级恢复机制。
